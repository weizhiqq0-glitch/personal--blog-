# 你的博客，前端和后端分别在哪里

前端是用户看到和操作的页面；后端负责数据、业务规则和权限。管理后台是给管理人员使用的网页，也属于前端，它调用后端接口来完成操作。

| 要讲清楚的部分 | 本项目对应内容 |
| --- | --- |
| 保存用户、文章和评论 | 数据库 users、articles、comments 表；backend/database.js 和 backend/postgres.js |
| 按条件查找文章或评论 | backend/api.js 的 GET /api/articles、GET /api/articles/:id/comments |
| 账号注册和登录规则 | backend/accounts.js，邮箱验证、唯一用户名、密码校验 |
| 密码不能明文保存 | backend/security.js，本地 scrypt；线上 backend/online-security.js 使用数据库密码函数 |
| 校验“谁可以做什么” | backend/permissions.js 与各接口中的 requireVerified、requirePermission、ownerOnly |
| 办事窗口，接收请求并返回结果 | backend/api.js 与 backend/accounts.js 的 HTTP API |
| 普通用户看到的页面 | frontend/src/App.jsx 及其他 React 组件 |
| 管理人员的操作页面 | 账号管理页面 ManagementPanel.jsx，文章编写和编辑界面，评论管理操作 |
| 用户头像 | backend/avatars.js，登录用户只能修改自己头像，头像按公开图片提供 |

代码仓库：https://github.com/weizhiqq0-glitch/personal--blog-

## 可以这样演示

1. 打开博客，说明这是前端，它通过 HTTP 请求后端读取文章。
2. 打开 backend/api.js，展示文章接口；说明后端查询数据库后返回 JSON。
3. 用普通账号登录，说明普通用户可评论但不能发布文章；展示 article.manage 的服务端校验，不能只靠隐藏按钮保护权限。
4. 用站主或有权限的管理员登录，演示文章发布、编辑与用户管理。
5. 展示数据库结构与密码哈希逻辑，但不要展示实际密码、邮箱列表、连接串或设备授权码。

本项目具有账号、文章、评论体系，前后端分离，源代码已发布 GitHub。是否满足对方的作业或考核标准，仍应逐条对照对方具体要求；“有后端”与“管理后台界面完整”是两个不同的验收项。

## 新版使用入口

- 博客前台：`#/`。站主登录后仍停留在博客，通过“管理后台”进入独立控制台 `#/admin`。
- 管理后台：文章、评论、账号与访客、问题反馈、板块内容各有独立页面。页面显示和实际操作都受账号权限限制。
- 登录报备：仅在 `#/admin/security` 查看及提醒；旧 `#/security` 链接也进入后台。必须同时满足站主登录和已绑定浏览器凭证，换设备登录站主也不能读报备。不要清除已绑定浏览器的网站数据。
- 额度与用量：`#/admin/quota`，仅站主可见，是邮件服务额度估算，不是现金钱包。
- 板块内容：`#/admin/content` 可管理项目、照片墙、音乐、说说、碎碎念、友链、关于。内容保存后公开显示；照片填写 HTTPS 图片直链，音乐填写有权使用的 HTTPS 音频直链，普通网页地址不能当音频播放。
- 站员：`#/members`，按站主、管理员、用户展示已验证且未封禁账号的头像和名称；不列访客，不公开邮箱、设备、登录信息或密码。
- 用户设置：屏幕右侧小按钮默认收起，点开浮层；点 ×、空白遮罩或按 Esc 收起。也保留完整页面 `#/settings`。可修改自己的头像、用户名、密码、主题，背景设置在 `#/appearance`。
- 圆盘导航：右下角“导航”打开各个公开板块，中心 × 或 Esc 关闭。

头像会随账号同步并公开展示。未设置头像时，取用户名首字；英文首字母大写。背景壁纸只保存在当前浏览器，不会替其他人换壁纸。Wallpaper Engine 的视频/图片可用；场景、pkg 和 Steam 创意工坊链接不能直接运行在网页中。
