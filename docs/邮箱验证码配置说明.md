# 邮箱验证码：EmailJS 配置说明

已改用 EmailJS，Brevo 注册可以暂停。根据官方价格说明，免费注册仅需姓名与邮箱，不需要银行卡；每月200次请求，适合初期低访问量博客。发送超额会被拒绝，不会自动收费。

## 1. 注册和连接邮箱

1. 打开 https://dashboard.emailjs.com/sign-up ，注册并验证邮箱。
2. 在 Email Services 点击 Add New Service，选择自己拥有的邮箱服务并完成连接/授权。支持 Gmail、Outlook 等；以控制台实际列表为准。先使用专门的发信邮箱更便于后续管理。
3. 先通过控制台测试，确认邮件能送达。记下 Service ID。

不需要购买域名，也不需要按 Brevo 的流程填写组织地址。发件邮箱会对收件人可见。只有平台实际支持的邮箱服务才可直接连接；不要把邮箱密码或授权码发到聊天。

## 2. 创建验证码模板

在 Email Templates 创建一个模板，按下面配置：

| 项目 | 内容 |
| --- | --- |
| To Email | {{to_email}} |
| Subject | 你的小站验证码 |
| From Name | 你的小站名称 |
| From Email | 勾选使用已连接服务的默认邮箱 |
| Content | 你的验证码是：{{code}}。5分钟内有效，若非本人操作请忽略。 |
| CC / BCC | 留空 |

保存并记下 Template ID。不要启用固定收件人或自动回复，否则验证码不会正确发送给注册用户。不要启用需要浏览器交互的模板 CAPTCHA，本项目通过后端接口控制验证码频率。

模板若默认记录发信历史，建议在模板设置关闭历史记录，避免在第三方控制台长期保留验证码内容。本博客数据库仍只保存验证码摘要。

## 3. 后端权限与密钥

在 Account / API Keys 查找 Public Key 和 Private Key。到 Account / Security 启用非浏览器/后端 API 请求，并启用私钥验证（选项文字以控制台为准）。不要把发送权限改成仅靠公开密钥即可调用。

本项目会同时提交 Public Key 和 Private Key；两者都只放在后端配置。发信服务配置不完整时拒绝发送，不会假装发送成功。若控制台实际要求付费或不提供后端请求设置，请先停止，不要购买套餐，先核实限制。

## 4. 写入 Cloudflare

完成以上设置后，双击项目根目录 ../tools/配置邮箱验证码.cmd，或本次输出的“配置邮箱验证码.cmd”。工具会引导 Cloudflare 登录，依次把以下值保存为 Worker Secrets：

- EMAILJS_SERVICE_ID
- EMAILJS_TEMPLATE_ID
- EMAILJS_PUBLIC_KEY
- EMAILJS_PRIVATE_KEY

工具随后重新部署后端。EMAIL_PROVIDER=emailjs 已写入 backend/wrangler.jsonc。无需在前端填写发信密钥，不要将这些值提交 GitHub。

本机运行：参考 backend/.env.example，将相同参数写入被忽略的 backend/.env，重启后端。

## 5. 实际验证

在博客点击获取验证码，检查目标邮箱与垃圾箱。收到邮件后完成注册；再检查站主绑定邮箱、找回密码。必须实际收件，才算邮件发送上线。当前只完成接口适配和隔离测试，尚未连接你的真实邮箱。

原有6—14位密码、五分钟有效验证码、每邮箱60秒重发、每小时六封、错误五次锁定和单次使用规则保留。EmailJS 自身还有每秒一次接口限制，高峰请求可能失败；适合初期低流量，后续访问量上来再迁移。个人邮箱还受其自身限额和反滥用规则约束。
