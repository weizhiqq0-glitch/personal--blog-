# 自动版本备份

使用博客工具箱或tools中的发布、更新后端、首次部署工具时，都会先执行压缩备份；备份失败则停止更新。

- 位置：项目内 `private/version-backups/`，搬迁时可随整个项目私密复制。
- 格式：ZIP，文件名包含UTC备份时间和完整Git提交号。
- 保留：最多3个不同源码版本，成功备份后自动删除最早的工具生成压缩包；同一提交已备份时不重复新增。
- 前端发布：优先备份本地记录的origin/main（上一次已知推送版本），无此记录才使用HEAD。
- 后端更新：备份运行工具时的HEAD，即最近一次已提交版本。先改后端再更新时，尚未提交的改动不在这个旧版备份中。

这是**源码版本备份**，不是线上平台完整快照：不会下载Cloudflare当前运行包，也不会包含Neon数据库、用户信息、.env、Secrets、node_modules、.git或未提交文件。若别人从其他电脑更新过仓库，本地origin/main可能滞后；先同步仓库再使用更新工具。不要绕开工具直接git push/npm run worker:deploy，否则不会自动触发本机备份。

该目录已被Git忽略，ZIP也被忽略，不会上传GitHub。只清理文件名符合本工具格式的ZIP，其他文件不删除。归档成功且可读取后才轮换删除，并有互斥锁防止同时更新时冲突。

恢复时先保留当前项目与私密配置，将ZIP解压到新目录，检查版本后再恢复源码，重新安装依赖、测试和部署。不要直接覆盖数据库；数据库和密钥按 [迁移与备份](迁移与备份.md) 单独备份恢复。
