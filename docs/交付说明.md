# 如何交付博客

## 原始要求对照

| 要求 | 实现 |
| --- | --- |
| 管理员和用户账号 | 邮箱验证码注册、登录、找回密码；普通用户、管理员、站主后端鉴权 |
| 文章 | 列表、详情、搜索；管理员/站主发布、编辑、删除 |
| 评论体系 | 用户发表评论、删除自己的评论；管理员/站主管理其他评论 |
| 前后端分离 | frontend为React页面，backend为独立Express API，通过HTTPS请求交互 |
| 发布到GitHub | 公开仓库、Actions检查、GitHub Pages发布前端 |

功能和源码已实现上述要求。正式交付前仍应按下面顺序在演示站验收当前部署，不能只看源码或截图。对方若另有技术栈、报告、录屏要求，应补充确认。

## 复制给对方的消息

> 你好，我完成了一个前后端分离的个人博客。
>
> GitHub源码仓库：https://github.com/weizhiqq0-glitch/personal--blog-
>
> 在线演示：https://weizhiqq0-glitch.github.io/personal--blog-/
>
> 前端采用React + Vite，后端采用Node.js + Express，线上数据库为PostgreSQL。已实现邮箱验证码注册登录、用户与管理员权限、文章发布/编辑/删除、评论发布与管理。前端部署在GitHub Pages，后端在Cloudflare Workers，数据库在Neon。
>
> 仓库README有启动、部署和测试方法，docs有功能与权限说明。你可以自行注册用户体验；管理员操作可由我演示，或单独授权专用测试账号。

发送这两个链接即可交付源码和演示。不要发送自己的站主密码、邮箱授权码、数据库连接串或服务商密钥。对方下载源码可使用GitHub的Download ZIP或git clone。

## 交付前演示一次

1. 工具箱更新后端、发布源码与前端；等待GitHub Actions最新检查和发布都变绿。仅文档变化无需更新后端。
2. 站主确认邮件额度已按EmailJS控制台校准。
3. 站主发布一篇自己写的演示文章，例如“博客功能演示”，避免私人信息。
4. 用无痕窗口作为访客打开文章，确认能阅读正文和评论。
5. 用能收信的另一邮箱正常注册普通用户，登录并发表评论。
6. 普通用户不能发布文章，不能修改管理角色；后端接口也必须拒绝。
7. 站主给专用测试用户授权管理员，再用该用户演示文章编辑和评论管理。
8. 演示后回收临时管理员权限，按需要删除演示评论，保留至少一篇正常文章。

录屏顺序可用“访客阅读 → 用户注册登录 → 评论 → 管理员文章管理 → GitHub目录说明”。录屏隐藏邮箱验证码、密码、密钥和用户管理里的私人邮箱。

## 对方要测试管理员时

让对方用自己的邮箱注册，再由你给专用账号授权管理员，测试后收回。不要借出站主。管理员可修改或删除内容；不希望正式内容受影响时，请在独立演示数据库/部署中验收。不要在公开README留下长期可用的管理密码。
