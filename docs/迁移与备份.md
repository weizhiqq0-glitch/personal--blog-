# 迁移与备份

源码、说明和工具全部在personal-blog文件夹。复制整个项目能带走程序，但云数据库、密钥和服务商授权需要单独处理。

| 内容 | 位置及处理 |
| --- | --- |
| 源码与依赖版本 | frontend、backend、scripts、tools、docs、.github；GitHub或复制项目 |
| 本地账号、文章、评论 | backend/data或自定义DB_PATH；停止后端后私密备份数据库及相关文件 |
| 线上账号、文章、评论、会话 | 自己的Neon数据库；通过Neon备份或PostgreSQL导出迁移 |
| 数据库连接串、邮件密钥 | Cloudflare Secrets、本地.env/.dev.vars（如有）；密码管理器或加密备份，新平台重新配置 |
| 前后端地址 | GitHub变量VITE_API_URL、后端CORS_ORIGINS；更换域名后同步修改并重新发布 |
| 服务商授权 | 新电脑重新登录GitHub/Cloudflare；不依赖复制授权缓存 |

**私密备份与公开交付分开。** 不要把含.env、backend/data、日志、截图的整个目录压缩发给陌生人。对外交付源码请用GitHub链接或GitHub下载ZIP。

## 换电脑，保留现有免费部署

1. 下载仓库或复制项目，安装Node.js 24 LTS和Git。
2. 在项目根目录执行 `npm --prefix backend ci` 和 `npm --prefix frontend ci`。
3. 恢复本地私密配置与本地数据库。线上数据仍在Neon，换电脑不会自动删除。
4. 需要发布时重新登录GitHub、Cloudflare。项目脚本均按相对目录查找文件。
5. 旧.lnk含电脑绝对路径，搬家后直接双击博客工具.cmd，按需新建快捷方式。

## 将后端搬到云服务器

最方便的方式是先保留Neon数据库，只迁移后端运行平台：

1. 服务器安装Node.js 24 LTS，克隆项目，在backend执行 `npm ci --omit=dev`。
2. 创建私密backend/.env，设置DATABASE_URL指向Neon、HOST=0.0.0.0、PORT、CORS_ORIGINS和邮件服务配置，参考backend/.env.example。
3. 使用npm start运行，配置进程管理、HTTPS与反向代理，不公开私密配置或数据库管理端口。
4. 新后端健康检查成功后，把GitHub的VITE_API_URL改为新HTTPS地址，重新发布前端，验收登录、文章和评论。
5. 数据库也搬时，暂停写入并备份Neon，用PostgreSQL工具完整导出/导入，核验后切换连接串。不能把PostgreSQL目录当SQLite文件复制。

改用SQLite需另外执行数据转换，不会自动从Neon同步。SQLite须放持久磁盘，同一数据库使用单个后端实例，备份前停止写入。

## 可重新生成的内容

node_modules是可用npm ci重装的依赖；frontend/dist与backend/.wrangler/build是构建产物；测试缓存、日志、过程工具和旧预览截图无需迁移。此次保留现有项目node_modules方便继续启动，清理已确认的构建产物与过程临时文件。数据库与真实配置不作垃圾删除。
